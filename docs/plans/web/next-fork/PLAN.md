Procédure de Synchronisation Upstream\n\nLa synchronisation régulière de `aphrody-labs/next.js` avec l'upstream `vercel/next.js` s'exécute selon un protocole contrôlé et sans risque de dérive.\n\n### 3.1. Configuration des remotes\nSur le clone de travail du fork :\n```bash\n# Vérifier la présence de l'upstream officiel\ngit remote get-url upstream 2>/dev/null || git remote add upstream https://github.com/vercel/next.js.git\n\n# Vérifier la présence du remote aphrody-labs (origin)\ngit remote get-url origin\n# -> https://github.com/aphrody-labs/next.js.git\n```\n\n### 3.2. Étape 1 : Rafraîchissement du miroir `canary`\n```bash\n# Récupérer l'état frais de l'upstream\ngit fetch upstream canary --tags\n\n# Se positionner sur canary\ngit checkout canary\n\n# Avancer le miroir strictement en fast-forward\ngit merge --ff-only upstream/canary\n\n# Pousser vers le miroir GitHub sans force-push\ngit push origin canary\n```\n*Si `--ff-only` échoue, STOP immédiat : anomalie sur la branche miroir.*\n\n### 3.3. Étape 2 : Intégration dans la branche `yolo`\nPour propager les mises à jour amont vers notre branche personnalisée sans écraser les correctifs Aphrody :\n```bash\ngit checkout yolo\n\n# Intégration par merge contrôlé (recommandé pour préserver l'historique et la traçabilité des conflits)\ngit merge canary -m "chore(sync): merge upstream canary into yolo"\n\n# En cas de conflit : résoudre manuellement, vérifier que les patches Aphrody sont préservés\n# Lancer les tests de non-régression Bun / Turbopack\n# Puis pousser :\ngit push origin yolo\n```\n\n---\n\n## 4. Matrice de Compatibilité : Bun Rust (Bun 1.4.2) & Next.js\n\nLe runtime Bun d'Aphrody/Yolo (`packages/bun`) est basé sur la réécriture en Rust (Bun 1.4.2, transition stabilisée en mai 2026). Next.js interagit avec ce runtime sur plusieurs plans critiques.\n\n### 4.1. État des tests d'intégration dans `packages/bun`\nLe banc de tests de Bun intègre déjà des validations de surface Next.js sous `packages/bun/test/integration/next-pages` :\n- **App de test :** `next-pages` avec Next.js `^16.1.0`, React `19.2.3`, TypeScript `5.9.2`.\n- **Commandes validées :** `next build`, `next dev` (Pages router).\n- **Vérifications :** Génération des chunks JS/CSS, manifestes de build, sortie SSR/SSG.\n- **Points de vigilance observés :**\n  1. `next/dynamic` et lazy-loading : résolution asynchrone des chunks sous le module loader Bun.\n  2. Spawns de workers Node (`child_process.fork` vs IPC Bun) : Next.js lance des workers Turbopack/Webpack qui nécessitent une émulation fidèle de `process.send` et des descripteurs IPC.\n  3. Gestion du cache de compilation : écriture concurrente dans `.next/cache` sous Bun FS.\n\n### 4.2. Matrice de compatibilité synthétique\n\n| Composant Next.js | Statut sous Bun Rust (1.4.2) | Remarques & Gaps |\n| :--- | :--- | :--- |\n| **Pages Router (`pages/`)** | **Supporté / Vert** | Validé par `test/integration/next-pages/test/next-build.test.ts`. |\n| **App Router (`app/`)** | **Partiellement validé** | React Server Components (RSC) et streaming HTML nécessitent un passage rigoureux sur `ReadableStream` Web standard. |\n| **Server Actions** | **En cours de qualification** | Gestion des headers d'action et mutation des cookies via `next/headers`. |\n| **Turbopack Dev (`next dev --turbo`)** | **Opérationnel** | Binaire natif Turbopack / bindings N-API Rust. |\n| **Turbopack Build (`next build --turbo`)** | **Expérimental** | Dépendance aux crates Rust Turbopack partagées. |\n| **Standalone Output (`output: 'standalone'`)** | **Prioritaire** | Mode requis pour la distribution Yolo (bundle minimal sans `node_modules` complet). |\n\n---\n\n## 5. Apport de Turbopack et de l'Écosystème Rust à la Stack Aphrody/Yolo\n\nL'intégration de Next.js et de ses fondations Rust apporte des synergies technologiques majeures pour Aphrody et Yolo :\n\n1. **Turbopack (Rust Engine) & Partage d'Infrastructures :**\n   - Turbopack est intégralement écrit en Rust (`crates/turbopack-*` dans le monorepo Next.js), articulé autour du moteur de calcul incrémental `turbo-tasks`.\n   - Ce moteur fournit un modèle de mémoïsation incrémentielle ultra-rapide sur graphe de dépendances en mémoire, directement connectable ou comparable à nos mécanismes d'invalidation dans Yolo/Aphrody.\n2. **SWC (`next-swc`) :**\n   - Les plugins de transformation de code SWC en Rust s'intègrent nativement avec nos pipelines de packaging.\n3. **Harmonisation Tooling & Performance :**\n   - Remplacement progressif des étapes JS lentes dans le pipeline de compilation frontend par des crates Rust natives sans surcoût d'appel FFI lourd.\n   - Alignement avec la doctrine d'Aphrody : un socle moteur précompilé en Rust, et du JS/TS uniquement en surface applicative légère.\n\n---\n\n## 6.
