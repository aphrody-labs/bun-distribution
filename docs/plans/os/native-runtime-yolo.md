# Native runtime YOLO — focused operating goal

Objective: qualify the installed Rust Aphrody runtime across CLI and MCP on this host. A correction closes only when source, built artifact and actually loaded process agree and a representative native call succeeds. BXC is retired; Web is Aphrody Web in Rust.

## Completion oracle

- Bun docs: native CLI from /tmp without APHRODY_BUN_DOCS and configured live MCP bun_docs_search("Bun.spawn") both return runtime/child-process, isError=false.
- Native Web: installed aphrody-mcp publishes unique tools and the configured live supported-languages call succeeds from existing Rust owners without launching BXC. Missing alias mappings are explicit gaps, never simulated support.
- Process proof: SHA256 of installed kernel/provider equals /proc/<pid>/exe; record parent PID and retain verified previous artifacts.
- Required scoped checks have real terminal exit codes: Rust check, strict Clippy, meaningful tests, release and format/diff checks. Full monorepo readiness remains a separate unclosed objective.

## One YOLO tick

1. Root selects one reproduced runtime failure or one failed oracle clause; records owner, reproduction and expected result.
2. Diagnostic agent reads current source/runtime using existing Rust CLI tools, reports at most one actionable ticket. No mutations or builds.
3. Implementation is assigned to exactly one owner. Validation agent independently checks the contract and existing evidence. They never edit the same file.
4. Root schedules one set of scoped gates after source freeze. Independent reads run together; Cargo checks sharing a build directory are queued once. Retry only after a code change, failure or changed evidence.
5. Activation agent alone backs up, installs and reloads the affected child. Root verifies the original live tool, records proof and commits only owned paths.
6. Compact the handoff to objective, active ticket, paths, completed evidence and next action. Continue only from this file and fresh probes.
