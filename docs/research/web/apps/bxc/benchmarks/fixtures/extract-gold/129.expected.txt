Configuring retries and timeouts
Quiver retries failed requests automatically. This page explains which failures are retried, how the backoff is computed, and how to override the defaults per command or globally.
Default behaviour
By default Quiver retries a request up to three times when the server returns a 429 or 5xx status, or when the connection is reset before a response arrives. Client errors such as 400 or 404 are never retried because repeating them cannot succeed.
Setting Default Description
retries 3 Maximum number of retries per request
backoff exponential Delay strategy between attempts
base_delay 250ms Delay before the first retry
timeout 30s Total time allowed for one request
Overriding settings
Settings can be passed as flags on any command or written to the configuration file. Flags take precedence over the file, and the file takes precedence over built-in defaults.
[http] retries = 5 backoff = "exponential" base_delay = "500ms" timeout = "60s"
Idempotency
Quiver only retries POST requests when an idempotency key is present, because retrying a non-idempotent request could create duplicate resources. Pass --idempotency-key or set it in the request template to enable retries for those calls.
quiver post /orders --data @order.json --idempotency-key "$(uuidgen)" --retries 5
