Understanding the storage engine
Loam stores data in an append-only log that is periodically compacted into sorted tables. Knowing how writes, reads and compaction interact helps you size disks and choose sensible settings.
Write path
Every write is appended to the write-ahead log and inserted into an in-memory table. When the memory table reaches its size limit it is frozen and flushed to disk as an immutable sorted file, and a new memory table takes its place.
Read path
A read checks the memory table first, then the sorted files from newest to oldest. Bloom filters attached to each file let Loam skip files that cannot contain the key, which keeps point lookups fast even with many files.
Operation Typical latency Notes
Point read (cached) 0.1 ms Served from memory
Point read (disk) 0.8 ms One file read after bloom filter checks
Range scan (1,000 keys) 6 ms Merges several files
Compaction
Compaction merges overlapping files, removes deleted and overwritten entries, and reclaims space. It runs in the background and is throttled so that it does not starve foreground requests, but heavy write workloads may need a higher compaction budget.
