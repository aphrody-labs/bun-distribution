A chess engine spends almost all of its time answering one question: if the game stopped here, who would be better and by how much? The answer is a single number, usually expressed in hundredths of a pawn, and the quality of that number determines how strong the engine plays.
Material and piece-square tables
The simplest evaluation counts material. A pawn is worth 100, a knight about 320, a bishop about 330, a rook 500 and a queen 900. On top of that, classical engines use piece-square tables, which add a bonus or penalty depending on where each piece stands. A knight in the centre controls more squares than a knight on the rim, so the table rewards it.
fn evaluate(board: &Board) -> i32 { let mut score = 0; for (square, piece) in board.pieces() { let value = MATERIAL[piece.kind()] + PST[piece.kind()][square.relative_to(piece.color())]; score += if piece.color() == Color::White { value } else { -value }; } score }
Tapered evaluation
A king hiding in the corner is safe in the middlegame and useless in the endgame, when it should march to the centre. Engines handle this by keeping two scores, one for the opening and one for the endgame, and blending them according to how much material is left on the board.
The move to neural evaluation
Modern engines replace most of this hand-written knowledge with a small neural network that takes the positions of all pieces as input. The network is designed so that it can be updated incrementally when a single piece moves, which keeps it fast enough to evaluate millions of positions per second on an ordinary processor.
The surprising part is how small these networks are. They are trained on billions of positions scored by deeper searches, and they capture patterns, such as the value of a pawn chain or an exposed king, that took human programmers decades to describe by hand.
