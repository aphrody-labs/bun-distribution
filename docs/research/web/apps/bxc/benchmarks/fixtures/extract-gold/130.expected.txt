Deploying to a Kubernetes cluster
This guide walks through deploying a Tessellate worker pool to an existing Kubernetes cluster using the official Helm chart, then verifying that workers register with the scheduler.
Prerequisites
You need a cluster running Kubernetes 1.28 or later, Helm 3.12 or later, and credentials that allow creating namespaces and cluster roles.
kubectl configured for the target cluster
Helm 3.12+
A scheduler URL and an API token
Install the chart
Add the repository, create a namespace, and install the chart with your scheduler URL. The token is stored as a Kubernetes secret and mounted into each worker pod.
helm repo add tessellate https://charts.tessellate.example kubectl create namespace tessellate helm install workers tessellate/worker-pool \ --namespace tessellate \ --set scheduler.url=https://scheduler.internal \ --set scheduler.tokenSecret=tessellate-token
Verify registration
Workers register within about thirty seconds of starting. Check the scheduler dashboard or list registered workers from the command line. If a worker does not appear, inspect its logs for authentication errors, which usually mean the secret name does not match.
kubectl -n tessellate get pods tessellate workers list --pool default
