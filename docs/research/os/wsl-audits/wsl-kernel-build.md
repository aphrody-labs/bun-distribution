# WSL kernel source build audit

Date: 2026-10-01. Source: https://github.com/microsoft/WSL2-Linux-Kernel
Pinned commit: `14794180686c2fb6307fbe359c359bec765249f3`.
Kernel source version: 6.18.40. Configuration: unmodified `Microsoft/config-wsl`, normalized with `olddefconfig` in a separate output directory.

## Source evidence

The upstream README at this revision specifies kernel/modules compilation, UAPI header installation, perf installation, and `Microsoft/scripts/gen_artifacts_vhdx.sh`. That script packages `<kernelrelease>/modules`, `<kernelrelease>/linux-headers`, and `<kernelrelease>/perf` into an ext4 image, then converts it to VHDX using qemu-img. It refuses an existing output filename. Source stays unmodified; no active WSL kernel is replaced and no host reboot is performed.

## Reproducible commands

```bash
src=.cache/upstream/WSL2-Linux-Kernel
out=.cache/upstream/build/aphrody/kernel
mkdir -p "$out"
cp "$src/Microsoft/config-wsl" "$out/.config"
make -C "$src" O="$out" olddefconfig
make -C "$src" O="$out" -j6
make -C "$src" O="$out" INSTALL_MOD_PATH="$out/modules" modules_install
make -C "$src" O="$out" headers_install INSTALL_HDR_PATH="$out/headers"
mkdir -p "$out/perf-build"
make -C "$src/tools/perf" O="$out/perf-build/" -j2 NO_JEVENTS=1 NO_JVMTI=1 NO_LIBTRACEEVENT=1 install DESTDIR="$out/perf" prefix=/
release=$(make -s -C "$src" O="$out" kernelrelease)
bash "$src/Microsoft/scripts/gen_artifacts_vhdx.sh" "$out/modules" "$out/headers" "$out/perf" "$release" "$out/modules.vhdx"
```

Concurrency is deliberately capped: 24 logical CPUs are available, but the machine is shared with other builds. Kernel uses six jobs and perf uses two. The initial available memory was approximately 12 GiB.

## Perf smoke validation

PMU parsing suites 8, 10 and 11 passed all eleven cases. Suite 7 skipped due to performance-event permissions. Suite 6 failed the upstream assertion at `tools/perf/tests/expr.c:251` (not in repo): Intel TSC frequency must be nonzero, but this WSL host does not expose that frequency in `/proc/cpuinfo`. The diagnostic is captured in `perf-test-parser.log`. The perf test process exits zero even with a failed subtest, so log results rather than process exit status are the evidence.

A make warning during perf compilation reported a generated object 0.39 seconds in the future; no source file had a future timestamp when checked afterwards. Binary installation and the selected parsing tests completed.
