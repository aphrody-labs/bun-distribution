## Reading the numbers

- **Base UI JS.** The old package was one module that called `React.forwardRef(...)` for Button, Switch, Checkbox and Tabs at
  module scope; a bundler must keep those calls (they may have side effects), so `M3Button` alone dragged in the Base UI code of
  all four: 22.5 KB (8.5 KB gzip). Removing the `export * as BaseUI` line changes nothing (22525 bytes either way); marking the four `forwardRef` calls pure gives 8254 bytes, which is what the per-primitive modules achieve structurally.
  Now every primitive is its own `'use client'` module and the package is `sideEffects: ["*.css"]`, so an unused module is dropped
  whole: `M3Button` alone is 8.4 KB (3.4 KB gzip), -63%; Button, Switch and Tabs together -10.7%. `import *` is all of Base UI plus
  38 wrappers (+1.6%).
- **CSS.** The old sheet styled four components (4.7 KB). The new one styles all 38 Base UI primitives (63.9 KB minified, 6.7 KB
  gzip) and is split: `css/core.css` plus the sheets of the components in use. Core and Button together are 10.0 KB (1.7 KB gzip);
  `examples/tauri` imports core, button and switch only. Every rule is in `@layer components`, so utilities always win.
- **Tailwind preset.** `preset.css` grew (15.2 KB to 37.7 KB minified) because it now carries the shape, typescale, spring and
  state utilities, the adaptive and Base UI variants and the spring easings. It is an input to Tailwind, never shipped: the app CSS
  for the same 25 classes is byte-identical (5.2 KB), and ten of the new utilities and variants add 3.2 KB (8.4 KB total,
  1.8 KB gzip). `@theme inline` keeps unused variables out.
- **m3-next client.** The provider no longer imports `@aphrody/m3-theme/react` (and with it material-color-utilities): the
  entry is 3.3 KB (1.7 KB gzip) instead of 94.3 KB (22.3 KB gzip), -96.5%. The colour engine (89.6 KB, 20.3 KB gzip) is a separate
  chunk, fetched only when the app sets a seed, variant or contrast different from the scheme the server inlined.
- **Server and build time.** `m3-next` index (config, scheme helpers) is not shipped to browsers; it grew 1.2% for `withM3`
  options and the typeface and script helpers.

## Build engine

`examples/app` cold, one machine, back to back, no other change: Turbopack 4.5 s, `--webpack` 15.3 s. Both run on Bun: the
`m3-next` runner puts a Bun `node` first on PATH so Turbopack's PostCSS and loader workers do not need Node (plain
`bun --bun next build` fails with `node: --bun is not allowed in NODE_OPTIONS`). Warm builds reuse the Turbopack file-system cache.
The example totals have no "before": the apps are new. The times were taken while other agents were building on the same
machine; a cold run before the bench took 25 s once, which is why the table shows medians of three.

## Not measured

Browser rendering (no browser was driven: the pages were fetched with curl and the HTML checked), runtime performance of the
components, and the Tauri webview itself (the export is built and its HTML checked, not loaded in Tauri).
