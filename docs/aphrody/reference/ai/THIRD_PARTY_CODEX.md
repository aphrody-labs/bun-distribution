# Third-party material from OpenAI Codex

Aphrody's coding agent ([delivery plan](../../plans/ai/PLAN.md)) implements a declared subset of the
*interface* of [openai/codex](https://github.com/openai/codex): configuration shapes, event
formats and app-server protocol. Client compatibility requires the declared subset and its conformance evidence. Codex is
licensed under the **Apache License 2.0**, the same licence as aphrody. This file records what
comes from it and how, as the licence's attribution terms require.

## Not taken

Upstream code aphrody does **not** reuse: the Codex TUI, `core`, the full app-server, the vendored
bubblewrap (LGPL, C — banned from aphrody's distribution; `bwrap` may only be driven as an optional
system binary), and anything tied to OpenAI account internals.

Adding material to this list: port with attribution, add a row here, keep the SPDX header, and note
the upstream path in the file's module documentation.

## Current code audit

The current source review used two local digests generated by `aphrody ingest`
from the pinned submodule (kept under ignored `var/`):

- `codex-rs/core/src/tools/sandboxing.rs`: approval decisions and session
  approval caching, the `ToolRuntime`/`SandboxAttempt` boundary, and sandbox
  selection helpers.
- `codex-rs/core/src/tools/orchestrator.rs`: the concrete approval → sandbox
  selection → tool attempt → policy-controlled retry flow.

These are analysis digests, not copied source. The implementation direction is
to adapt these narrow boundaries to Aphrody's no-HITL, fail-closed policy and
own runtime interfaces. Do not transplant Codex `core` wholesale or bundle its
vendored LGPL bubblewrap. The present audit found Aphrody's sandbox runner
silencing backend setup errors and its Unix backend ignoring the requested
policy; the enforcement fix belongs in `aphrody-os`, and AI shell/file callers must also route through it before the product
advertises restricted execution.
