# R2 public domains, 2026-10-10

Owner-authorized names: `assets.aphrody.com` → `aphrody-assets` and
`dist.aphrody.com` → `aphrody-dist`. Existing `cdn` and `downloads` service
identities are preserved. No registrar, host, bucket content or credential change
is made by this adapter.

[cloudflare-r2-domains.ps1](../../../../scripts/aphrody/tools/infra/cloudflare-r2-domains.ps1)
fills the demonstrated installed Infra capability gap: `aphrody infra --help`
has no Cloudflare/R2 command. It uses the existing isolated native DPAPI token.
Cloudflare API contracts: [attach](https://developers.cloudflare.com/api/resources/r2/subresources/buckets/subresources/domains/subresources/custom/methods/create/),
[update](https://developers.cloudflare.com/api/resources/r2/subresources/buckets/subresources/domains/subresources/custom/methods/update/)
and [public buckets](https://developers.cloudflare.com/r2/buckets/public-buckets/).
There is no CNAME to an `r2.dev` hostname; Cloudflare owns the generated R2 DNS.

```powershell
powershell -NoProfile -File scripts/tools/infra/cloudflare-r2-domains.ps1 -Action Plan
powershell -NoProfile -File scripts/tools/infra/cloudflare-r2-domains.ps1 -Action Apply
powershell -NoProfile -File scripts/tools/infra/cloudflare-r2-domains.ps1 -Action Verify
```

Plan is the default. Account, zone, bucket and default-jurisdiction identities
must match. Conflicting DNS is refused. Before any write, the complete DNS and
domain state is saved under the configured Aphrody home's
`protected-backups/dns/r2-domains-*`, with owner/SYSTEM-only inherited ACLs and
a checksum-verified duplicate. Apply creates or updates only these two custom
domains, enabled with minimum TLS 1.2, reads settings back and checks unrelated
DNS byte-equivalence. It is idempotent after successful registration.

Cloudflare's documentation permits connecting a bucket once a zone exists in
the account. Pending-zone registration is therefore attempted as preparation;
it never establishes production qualification. Verify requires an active zone,
active domain ownership and SSL, then public TLS-validated GETs of approved
existing JSON objects with SHA-256 equality against the current managed endpoint:
`m3/symbols/material-symbols-index.json` (not in repo) and
`aphrody/manifest.json` (not in repo), object keys on the managed public endpoints.
It also calls native `aphrody web browser snapshot --json` for both public custom
URLs and checks URL/object identity. Full snapshots and object bytes remain in
the protected evidence directory. No provider secret appears in output.
