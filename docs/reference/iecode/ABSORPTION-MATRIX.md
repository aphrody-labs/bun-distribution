# IECODE absorption matrix

This is the ownership boundary for code recovered from `nie`, `rg`, `vps` and the Aphrody
repositories. IECODE receives portable libraries and binding contracts. `nie`/`niers` remains the
owner of Victory Road and IEVR-specific runtime behaviour. `rg` and `vps` are audit sources, not
new IECODE applications.

| Source surface | IECODE destination | Boundary |
| --- | --- | --- |
| `nie-formats`, `nie-data` | `crates/core` and its format libraries | Pure decoding, validation and typed data only |
| `nie-emu` registry and external emulator adapters | `crates/emu`, `crates/pipeline` | Historical IEVR source; IECODE owns the resulting metadata and in-process/FFI contracts |
| `nie-video`, IETV/Inazuma TV contracts | `packages/iecode-core`, `crates/video` | Catalog, URL, player and media metadata; no scraper, bot or database service |
| `iecode-cpp`, `iecode-csharp`, `node-api-dotnet` | `src/iecode-*`, `IECODE.sln` | Native format/reference implementations behind the shared Rust FFI |
| Python extraction tools | `src/` and the root `uv` workspace | Offline adapters and fixtures; no second owner of a format |
| `melonDS` | `crates/emu` registry reference | Pinned upstream DS compatibility oracle; no ROM, BIOS, key or user data |
| `rose-griffon/rg` | `packages/iecode-core` only where a contract is portable | No `db`, `ui`, website, Discord bot, service or generated content |
| `aphrody-code/vps` | No source import | Deployment, Nginx, systemd, credentials, backups and release state stay operational |

## Merge rules

- A capability has one owner. A wrapper may expose it through Rust FFI, Bun or .NET, but it must
  not reimplement it.
- `crates/core` is the Rust library facade. `apps/iecode-cli`, Bun, .NET and C/C++ are bindings.
- `crates/pipeline` validates ordered, bounded stage manifests. Validation has no filesystem,
  process, network or emulator side effect.
- Third-party emulators and extraction tools remain source references or dynamic-library adapters;
  they are not copied into `src/` and no proprietary game dump, key, BIOS, ROM or APK is tracked.
- A source audit does not authorize deployment changes. The `vps` history is used only to detect
  obsolete service ownership and release coupling.

The machine-readable audit is generated by `../src/aphrody-infra/scripts/iecode/github-history-audit.sh` (owned by aphrody-infra); its measured
repository counts and relevant `rg`/`vps` commits are recorded in
[`history/APHRODY-AUDIT.md`](../../research/iecode/history/APHRODY-AUDIT.md).
