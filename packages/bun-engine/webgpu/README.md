# WebX shader and baseline graphics wire contract

`vkwebgpu-webx-wire.patch` targets the pinned `vendor/vkwebgpu-icd` source owner at commit `2202e49d617877b2a114b575a3e22777910b2e5b` and is applied only to a qualified build tree. It aligns the minimal graphics producer payloads with the canonical parser in `vendor/webx/protocol/commands.h` and `vendor/webx/harness/vkwebgpu-plugin.mjs`; neither imported source owner is edited in place.

The current tranche covers raw SPIR-V shader creation (the host's injected Naga 30 WASM translator owns SPIR-V-to-WGSL), pipeline layout, a single-subpass `VkRenderPass`, framebuffer, 2D image/image view, graphics pipeline, swapchain lifecycle, and existing command-buffer queue submission for a vertex/fragment draw. Pipeline raster/depth records are assembled from explicit little-endian fields into zeroed wire-layout records; no Vulkan process memory or padding is copied. WebGPU shader compilation errors are fatal. Guest IPC errors are propagated and failed create paths release their local handles.

The baseline is one single-sample B8G8R8A8_UNORM or R8G8B8A8_UNORM color attachment, one graphics subpass, one framebuffer layer, dynamic viewport and scissor, one vertex plus one fragment stage, fill rasterization, and no depth/stencil, logic operation, primitive restart, depth clamp/bias, multisample extensions, pipeline `pNext`, or render-pass dependencies. Swapchain images use the host's WebGPU canvas path. `VkRenderPass2`, dynamic rendering, compute pipelines, and non-vertex/fragment stages fail explicitly or remain outside this qualification tranche.

The browser fixture compiles real GLSL to SPIR-V on the VPS and tests translation, actual WebGPU shader-module compilation, resource and pipeline dispatch, command submission, present, validation scopes, and pixel readback. This makes no general Vulkan, DXVK, or arbitrary application compatibility claim. Other permissive host handlers need independent qualification before their behavior is treated as supported.
