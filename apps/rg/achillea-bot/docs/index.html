Achillea Backend

Bot Discord + API REST + WebSocket — moteur de la plateforme Achillea

Node.js 20+ TypeScript 5.x Discord.js 14 PostgreSQL 16 Mikro-ORM 6 TsED 7 BullMQ 5 Socket.io 4

Presentation

Achillea Backend est le coeur de la plateforme Achillea. Un seul processus Node.js combine trois roles :

┌─────────────────────────────────────────────────────────────┐ │ AchilleaBackend │ │ │ │ ┌──────────────┐ ┌──────────────┐ ┌──────────────────┐ │ │ │ Bot Discord │ │ API REST │ │ WebSocket │ │ │ │ (discordx) │ │ (TsED) │ │ (Socket.io) │ │ │ │ │ │ │ │ │ │ │ │ Commandes │ │ Controleurs │ │ Namespace │ │ │ │ Evenements │ │ Middlewares │ │ /notifications │ │ │ │ Boutons │ │ DTOs │ │ │ │ │ └──────┬───────┘ └──────┬───────┘ └────────┬─────────┘ │ │ │ │ │ │ │ └────────┬────────┴────────────────────┘ │ │ │ │ │ ┌────────┴────────┐ │ │ │ Services DI │ (tsyringe - Singleton) │ │ │ Mikro-ORM │ (PostgreSQL) │ │ │ BullMQ │ (Redis) │ │ └─────────────────┘ │ └─────────────────────────────────────────────────────────────┘

Le projet est base sur TSCord v2.4, un framework Discord.js/discordx enrichi d'injection de dependances, d'un ORM et d'une API REST integree.

Fonctionnalites principales

Clans

Creation, gestion des membres (roles, distinctions), invitations, candidatures, equipes, XP collectif

Tournois

Creation, inscriptions, seeding, brackets (single/double elim, round robin), scores, check-in

Ranked

Queue matchmaking 1v1/2v2, calcul Elo, lobbies automatiques, paliers de rang

Interclans

Matchs clan vs clan, lineups verrouillees, lobbies 1v1 par position

Organisations

Entites organisatrices de tournois, validation admin

Votes

Systeme de gouvernance (propositions, strategies unanimite/majorite/2-3)

Notifications

Push temps reel via WebSocket + messages Discord

Unit of Work Mikro-ORM em.flush() Les changements sont accumules puis executes en transaction
Identity Map Mikro-ORM Chaque entite n'est chargee qu'une fois par contexte
Repository Mikro-ORM repos Acces aux donnees par entite
DTO class-transformer Serialisation/deserialisation controlee entre couches
Guard/Middleware @Guard() (discordx) + middlewares TsED Protection declarative des commandes et routes
Heritage Event → Tournament/Ranked/Interclan Discriminateur de type sur l'entite abstraite
Event-Driven EventManager (RxJS) Bus d'evenements internes pour decouplage

API REST

L'API est construite avec TsED (Express + decorateurs TypeScript). Chaque controleur utilise @Controller('/prefix') et les routes protegees utilisent le middleware CookieAuthorize. 

// Exemple de controleur TsED
@Controller('/clans')
export class ClansController {
  @Get('/')
  async list(@QueryParams() query: PaginationParams) {
    return this.clanService.findAll(query);
  }

  @Post('/create')
  @Use(CookieAuthorize)
  async create(@BodyParams() dto: CreateClanDTO) {
    return this.clanService.create(dto);
  }
}

Systeme de guards (14)

Les guards sont des middlewares qui s'executent avant le handler de commande : 

// Exemple de guard custom
async function NoClan(interaction: CommandInteraction, client: Client, next: Function) {
  const user = await em.findOne(ClanMember, { user: interaction.user.id });
  if (user) {
    return interaction.reply({ content: 'Vous etes deja dans un clan.', ephemeral: true });
  }
  next(); // Continuer vers le handler
}

Le serveur Socket.io gere les notifications temps reel via le namespace /notifications : 

// Cote serveur — namespace avec middleware d'authentification
const notificationsNs = io.of('/notifications');

notificationsNs.use((socket, next) => {
  // Verifier le cookie JWT
  const token = parseCookie(socket.handshake.headers.cookie);
  if (!verifyToken(token)) {
    return next(new Error('Non autorise'));
  }
  next();
});

notificationsNs.on('connection', (socket) => {
  socket.join(`user:${socket.data.userId}`);

// Emission ciblee vers un utilisateur

Jobs et queues

Le backend utilise BullMQ avec Redis pour les taches asynchrones et differees : 

import { Queue, Worker } from 'bullmq';

const connection = { host: '127.0.0.1', port: 6379, db: 0 };

// Definition de la queue
const clanQueue = new Queue('clan', { connection });

// Planifier une verification dans 24h
await clanQueue.add('checkClanMemberCount', { clanId }, {
  delay: 24 * 60 * 60 * 1000  // 24 heures
});

// Worker qui traite les jobs
const worker = new Worker('clan', async (job) => {
  if (job.name === 'checkClanMemberCount') {
    const clan = await em.findOne(Clan, job.data.clanId, { populate: ['members'] });
    if (clan && clan.members.length < 5) {
      await disbandClan(clan);
    }
  }
}, { connection });

@Discord()
class MaCommande {
  @Slash({ description: 'Description', name: 'ma-commande' })
  @Guard(NotBot, Blacklist, /* autres guards */)
  async handler(
    @SlashOption({
      name: 'option',
      description: 'Description de l\'option',
      type: ApplicationCommandOptionType.String,
      required: true
    })
    option: string,
    interaction: CommandInteraction
  ) {

  }
}

Structure d'un controleur API

@Controller('/mon-endpoint')
export class MonController {
  @Inject() private monService: MonService;

  @Get('/')
  async list() { return this.monService.findAll(); }

  @Post('/')
  @Use(CookieAuthorize)
  async create(@BodyParams() dto: CreateDTO) {
    return this.monService.create(dto);
  }
}
