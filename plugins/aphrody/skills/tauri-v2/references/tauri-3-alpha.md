# Tauri 3 alpha: what changes from v2

Tauri 3.0 is in alpha (`3.0.0-alpha.0` on 2026-09-13, `alpha.3` on 2026-09-26; MSRV 1.95).
v2 (2.12.x) remains the stable line. Use v3 only when the project already depends on it
(`tauri = "=3.0.0-alpha.N"` in `Cargo.toml`); pin the exact alpha, because every alpha has
breaking changes. Source: GitHub releases `tauri-v3.0.0-alpha.*` of tauri-apps/tauri.

## Runtime selection (alpha.0)

The webview runtime is chosen at build time, not through `tauri` Cargo features:

```rust
tauri::Builder::default()
    .runtime(tauri_runtime_wry::Wry::default()) // or tauri_runtime_cef::Cef::default()
    .run(tauri::generate_context!())
    .expect("error while running tauri application");
```

- Apps depend on `tauri-runtime-wry` (or `tauri-runtime-cef`) directly. Without a runtime,
  building fails with `RuntimeNotConfigured`.
- Removed `tauri` features: `wry`, `cef`, `x11`, `dbus`, `macos-proxy`.
- `devtools`, `macos-private-api` and `unstable` must be enabled on the runtime crate.
- Removed items: `tauri::Wry`, `tauri::WryHandle`, `tauri::Cef*`, `tauri::tao`, `tauri::wry`
  (use `tauri_runtime_wry::{tao, wry}`), `tauri::webview_version()` (use
  `App::webview_version` / `AppHandle::webview_version`).
- Default generic runtime is the type-erased `tauri::DynRuntime`, so `AppHandle`, `Window`,
  `Webview` can still be written without naming the runtime.
- Runtime-specific APIs moved to extension traits: `tauri_runtime_wry::{AppHandleWryExt,
  AppWryExt, WebviewWryExt, WebviewWindowBuilderWryExt, WebviewBuilderWryExt}` (e.g.
  `with_wry_webview`, `create_tao_window`); `tauri_runtime_cef::{WebviewCefExt, ...}`.
- Android: `tauri::android_binding!` moved to `tauri_runtime_wry::android_binding!`.
- Custom scheme URL format comes from the runtime; `tauri::test::MockRuntime` uses
  `tauri://localhost` on every platform (tests that used `http://tauri.localhost` must change).
- Resources are no longer copied to `target/`; unbundled runs read them from source paths.
- ACL: autogenerated `allow-<cmd>` / `deny-<cmd>` are materialised on demand, and the app
  manifest gains `allow-*` / `deny-*` covering all its commands.

## Plugin API (alpha.2, alpha.3)

- `plugin::Builder::js_init_script` -> `initialization_script`;
  `js_init_script_on_all_frames` -> `initialization_script_on_all_frames`.
- `Plugin::initialization_script` returns `Option<InitializationScript>`
  (`tauri::webview::InitializationScript`, `for_main_frame_only`).
- `Plugin::extend_api` -> `Plugin::run_invoke_handler`.
- `Invoke::state` / `state_ref` removed: use `Manager::state` on `invoke.webview_ref()`;
  `tauri::StateManager` is no longer exported.
- `Plugin` now requires `Sync`; hooks (`window_created`, `webview_created`, `on_navigation`,
  `on_page_load`, `on_event`, `run_invoke_handler`) take `&self` and may run concurrently.
  Builder hooks take `Fn + Send + Sync`. Use interior mutability for hook state.
- New `Plugin::cleanup_before_exit` / `plugin::Builder::on_cleanup_before_exit` (runs even
  on `AppHandle::restart`), good for killing sidecars.

## Main thread and menus (alpha.3)

- `run_on_main_thread` moved to the `tauri::Manager` trait; new
  `Manager::run_on_main_thread_blocking` returns the closure's result.
- `TrayIcon::with_inner_tray_icon` -> `with_inner_blocking`; menus gain `with_inner_blocking`.
- Unstable `Window::add_child` lost its position/size parameters; use
  `WebviewBuilder::bounds` / `size` / `position`.

## Upgrade checklist

1. Bump `tauri`, `tauri-build`, the runtime crate, `@tauri-apps/api`, `@tauri-apps/cli`
   and every official plugin to their v3 alphas together, pinned with `=` (alpha numbers
   differ per crate, e.g. `tauri` alpha.3 with `tauri-build` alpha.2; check each on crates.io).
2. Add `.runtime(...)` to the builder and move runtime features to the runtime crate.
3. Replace removed re-exports and runtime-specific calls with the `*Ext` traits.
4. Make custom plugins `Sync` and switch hooks to `&self`.
5. Re-run `cargo check` and the app's IPC tests; fix `tauri://localhost` origins in tests.
